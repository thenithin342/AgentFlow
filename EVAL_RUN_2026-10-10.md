## Inconclusive runs

### Application

The initial full run was interrupted after a long silent period. A one-row retry completed after roughly two minutes and consumed 29,018 graph tokens across 9 calls plus 6 searches, far above the historical average. `--resume` then loaded the 20-row report from the default `evals/results/` directory instead of the requested run directory and rewrote it as a new report with zero current tokens and near-zero wall time. The apparent 4.17/5 full result is historical and invalid as evidence for this run.

### RAG-QA

A one-row bounded retry failed after 57.5 seconds because Google embeddings returned a 503 connection/handshake timeout. The report correctly had one error and zero valid scores. `--resume` then imported all 25 historical rows from the default results directory, producing a new-timestamp report with zero current calls. Its displayed faithfulness 0.708 is historical and invalid as evidence for this run.

## Highest-priority fixes

1. Fix result isolation and completeness. Pass the selected output directory into every runner, resume only from that directory, include dataset/config/model/git provenance, reject duplicate or stale rows, require the expected row count, and make missing/error rows fail the command.
2. Replace the thread-based timeout. The current executor waits for the worker during shutdown after a timeout, so a stuck graph call can freeze a nightly job. Use cancellable async calls or terminate isolated worker processes.
3. Fix the two safety behaviors in the product: refuse high-stakes legal drafting or provide a guarded template with a clear boundary, and mask user PII instead of echoing it.
4. Turn generator evaluation into a real component eval by generating an answer from query + context, then judge that output. Keep golden-reference scoring only as judge calibration.
5. Redesign retrieval precision. Use precision over returned relevant candidates, MRR/nDCG, or dense relevance labels; the current 0.80 precision@5 threshold is unattainable.
6. Make RAG-QA corpus-backed and resilient. Test PDF ingestion/retrieval with distractor chunks, add bounded retry/backoff for embedding 503s, and use unique scratch storage per run.
7. Add hard cost/tool budgets to research and blog agents. The fresh one-row application run showed a 29K-token, six-search outlier; cap iterations, tokens, searches, and wall time and report budget exhaustion distinctly.
8. Repair CI semantics: apply `--limit` and `--dry-run` when `all` is selected, restore artifacts before resume or disable resume in fresh jobs, enforce absolute quality gates as well as baseline deltas, and fail if expected metrics are absent.

## Phase recommendation

Phases 0, 1, and 2 are substantially implemented. Phase 3 is implemented but not trustworthy enough to call operationally complete. Spend the next iteration on items 1–5 above, rerun one clean full Tier B batch from a single commit, and accept a new baseline only when every report has complete provenance and no stale rows. Then proceed to Phase 4 with a real LangSmith target, black-box SSE/API tests, live latency/reliability/cost monitors, and feedback capture.
